KeyboardLayout

Switches Enhanced Input bindings automatically when a player's physical keyboard isn't QWERTY — WASD becomes ZQSD on French, no extra work.

Unreal Engine 5.8 · Windows (event-driven) · Enhanced Input integration

How it works

Author one Input Mapping Context in QWERTY. KeyboardLayout detects the player's actual layout and swaps each key to its physical-position equivalent automatically:

Same physical keys, same action — only the printed letter differs. Only the letters that actually move get swapped (4 for AZERTY, 2 for QWERTZ, the whole alphabet for Dvorak); digits, Space, mouse and gamepad are untouched since those already work identically on every layout. Detection reacts instantly to Windows' own layout-change event, so it never polls.

Setup

  1. Enable the KeyboardLayout plugin (pulls in Enhanced Input automatically).
  2. Project Settings → Game → Keyboard Layout → set Canonical Mapping Context to the Input Mapping Context your project already uses.
  3. Done. AZERTY, QWERTZ and Dvorak players now get an auto-translated copy of it.

Need different bindings for one family on purpose (or Turkish F, not auto-translated yet)? Add it to Layout Family Mappings — it overrides the automatic translation for that family only. To target one specific player at runtime instead, call SetContextForLayoutFamily — see the quick starts below.

EKeyboardLayoutFamilyEnum
QWERTYThe default: English, Spanish, Italian, every non-Latin script, and anything not listed below.
AZERTYFrance, Belgium, Luxembourg, Monaco.
QWERTZGermany, Austria, Swiss French/German, Czech, Slovak, Hungarian. Y/Z swap only — never touches WASD.
DvorakUS-Dvorak and its one-handed variants. Full rearrangement; told apart from QWERTY by id, not language.
TurkishF"F klavye", distinct from the QWERTY-based Turkish Q most users have. Also told apart by id.
UKeyboardLayoutSettingsDeveloper Settings · Project Settings → Game → Keyboard Layout
Canonical Mapping ContextYour QWERTY-authored context. Auto-translated for any family with no entry below. Unset disables auto-translation.
Canonical Layout FamilyWhat it was authored for. Default QWERTY.
Layout Family MappingsMap of Family → Input Mapping Context for hand-authored exceptions (or Turkish F). Overrides auto-translation per family.
Mapping PriorityInt, default 0 — passed to AddMappingContext.
Auto Apply To Local PlayersBool, default true. false disables both of the above; only SetContextForLayoutFamily overrides apply.
UKeyboardLayoutInputSubsystemLocal Player Subsystem
SetContextForLayoutFamilyCallable · (LayoutFamily, Context) — per-player override, re-applied immediately if it's the current family. None makes this player ignore that family.
ClearLayoutFamilyOverridesCallable — clears overrides set above.

Detection is event-driven on Windows today, behind one internal interface — another platform is a matter of adding one more implementation of it.
