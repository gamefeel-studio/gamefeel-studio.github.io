KeyboardLayout

Detects the OS keyboard layout and switches Enhanced Input mapping contexts automatically — no polling, no per-project C++.

Unreal Engine 5.8 · Windows (event-driven) · Enhanced Input integration

Overview

KeyboardLayout watches the keyboard layout of the OS window that has focus and reports it as a plain EKeyboardLayoutFamily enum value (QWERTY, AZERTY, QWERTZ). It deliberately doesn't expose the OS language: on Windows, the virtual-key codes for the Latin alphabet only shift for layouts that actually rearrange it — AZERTY, and QWERTZ's Y/Z swap — while every other language (English, Spanish, Italian, Portuguese, Dutch, Polish, Turkish, and every non-Latin script, which keeps its Latin shortcuts pinned to the QWERTY positions) behaves exactly like QWERTY for gameplay bindings. So there are only ever a handful of families to map, not one entry per language. On Windows it reacts to the WM_INPUTLANGCHANGE system message, so detection is instant and costs nothing while the layout isn't changing — it never polls.

A single map in Project Settings says which Input Mapping Context each family gets. A per-player subsystem watches for layout changes and adds/removes the matching context on the player's EnhancedInputLocalPlayerSubsystem automatically, so a project only has to fill in that map — it never calls AddMappingContext itself.

Setup

  1. Enable the KeyboardLayout plugin. It depends on Enhanced Input, which is enabled automatically.
  2. Open Project Settings → Game → Keyboard Layout.
  3. Add one entry per layout family you want to react to in Layout Family Mappings: pick the family, assign the Input Mapping Context to apply for it. Most projects only need one entry for AZERTY (ZQSD) on top of their default QWERTY bindings. A family left out is simply not reacted to.
  4. Set Mapping Priority if these contexts need to outrank (or lose to) others already active.

Every local player picks this up automatically. To give one specific player a different context instead, call SetContextForLayoutFamily on its KeyboardLayoutInputSubsystem — see the quick starts below.

API reference

UKeyboardLayoutSubsystemEngine Subsystem

Owns detection and is the single source of truth for the current layout family. Exists for the lifetime of the engine.

OnKeyboardLayoutChangedEvent · (NewLayoutFamily: Keyboard Layout Family) — broadcast whenever the detected layout family changes.
GetCachedLayoutFamilyPure · returns Keyboard Layout Family — the last detected family, without re-querying the OS.
GetCachedLayoutIdPure, Advanced · returns String — the last detected raw platform layout id (Windows HKL as 8 hex digits). Only useful to tell apart layouts that share a family, e.g. France AZERTY vs. Belgian AZERTY.
UKeyboardLayoutBPLibraryBlueprint Function Library
GetCurrentKeyboardLayoutFamilyPure, static · returns Keyboard Layout Family — shortcut for UKeyboardLayoutSubsystem::GetCachedLayoutFamily, usable from any Blueprint without fetching the subsystem first.
GetCurrentKeyboardLayoutIdPure, static, Advanced · returns String — shortcut for GetCachedLayoutId.
EKeyboardLayoutFamilyEnum

Unknown, QWERTY, AZERTY, QWERTZ. On Windows, the virtual-key codes for the Latin alphabet only move off QWERTY for layouts that actually rearrange it: AZERTY (France, Belgium, Luxembourg, Monaco) and QWERTZ's Y/Z swap (German-speaking layouts, and Swiss French). Every other language — including every non-Latin script, which keeps its Latin shortcuts pinned to QWERTY positions — resolves to QWERTY. Recognizing another family is a one-line addition in the plugin's C++, no API change.

UKeyboardLayoutSettingsDeveloper Settings · Project Settings → Game → Keyboard Layout
Layout Family MappingsMap of Keyboard Layout Family → Input Mapping Context. A family left out isn't reacted to. Edited directly as a map in Project Settings — no separate asset.
Mapping PriorityInt, default 0 — priority passed to AddMappingContext for every context above.
Auto Apply To Local PlayersBool, default true — set to false to ignore Layout Family Mappings and only react to per-player overrides set via SetContextForLayoutFamily.
UKeyboardLayoutInputSubsystemLocal Player Subsystem

Applies the project's (or this player's own) layout family mappings to this player's Enhanced Input contexts. One instance per local player.

SetContextForLayoutFamilyCallable · (LayoutFamily: Keyboard Layout Family, Context: Input Mapping Context) — overrides, for this player only, which context that family gets, and re-applies immediately if it's the current one. Pass None as Context to make this player ignore that family.
ClearLayoutFamilyOverridesCallable · clears every override set via SetContextForLayoutFamily, falling back to Layout Family Mappings again.

Platform support

Detection is event-driven on Windows today. Detection lives behind a single internal interface, so support for another platform is a matter of adding one more implementation of it — nothing else in the plugin needs to change.
