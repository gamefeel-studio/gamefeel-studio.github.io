KeyboardLayout

Detects the OS keyboard layout and switches Enhanced Input mapping contexts automatically — no polling, no per-project C++.

Unreal Engine 5.8 · Windows (event-driven) · Enhanced Input integration

Overview

KeyboardLayout watches the keyboard layout of the OS window that has focus and reports it as a plain string id (the Windows HKL, e.g. 0000040C for a French AZERTY layout, 00000409 for US QWERTY). On Windows it reacts to the WM_INPUTLANGCHANGE system message, so detection is instant and costs nothing while the layout isn't changing — it never polls.

A separate data asset maps those ids to the Input Mapping Context(s) a project wants active for each layout. A per-player subsystem watches for layout changes and adds/removes the matching context on the player's EnhancedInputLocalPlayerSubsystem automatically, so a project only has to fill in a table — it never calls AddMappingContext itself.

Setup

  1. Enable the KeyboardLayout plugin. It depends on Enhanced Input, which is enabled automatically.
  2. Create a Keyboard Layout Mapping Asset (right-click in Content Browser → Miscellaneous → Data Asset → KeyboardLayoutMappingAsset).
  3. Add one entry per layout you want to react to: its layout id(s), the Input Mapping Context to apply, and its priority. Set Default Mapping for every other layout.
  4. Open Project Settings → Game → Keyboard Layout and set Default Mapping to that asset. Every local player picks it up automatically.

To target a specific player instead of the whole project, call SetMappingAsset on its KeyboardLayoutInputSubsystem.

API reference

UKeyboardLayoutSubsystemEngine Subsystem

Owns detection and is the single source of truth for the current layout. Exists for the lifetime of the engine.

OnKeyboardLayoutChangedEvent · (NewLayoutId: String) — broadcast whenever the detected layout changes.
GetCachedLayoutIdPure · returns String — the last detected layout id, without re-querying the OS.
UKeyboardLayoutBPLibraryBlueprint Function Library
GetCurrentKeyboardLayoutIdPure, static · returns String — shortcut for UKeyboardLayoutSubsystem::GetCachedLayoutId, usable from any Blueprint without fetching the subsystem first.
UKeyboardLayoutMappingAssetData Asset

The layout → Input Mapping Context table. Editor-only data: adding a layout or changing its context never touches C++.

MappingsArray of entries, each with Layout Ids (String[]), Mapping Context (Input Mapping Context), and Priority (Int).
Default MappingEntry applied when no entry in Mappings matches the detected layout.
UKeyboardLayoutSettingsDeveloper Settings · Project Settings → Game → Keyboard Layout
Default MappingMapping asset applied automatically to local players.
Auto Apply To Local PlayersBool, default true — set to false to assign mapping assets per player via SetMappingAsset instead.
UKeyboardLayoutInputSubsystemLocal Player Subsystem

Applies the active mapping asset to this player's Enhanced Input contexts. One instance per local player.

SetMappingAssetCallable · (InMappingAsset: Keyboard Layout Mapping Asset) — swaps which mapping asset drives this player and re-applies it for the current layout immediately. Pass None to clear it.

Platform support

Detection is event-driven on Windows today. Detection lives behind a single internal interface, so support for another platform is a matter of adding one more implementation of it — nothing else in the plugin needs to change.
